# 결정 기록 (decisions.md)

개발 중에 묻지 않고 내린 결정과 그 이유를 적는다. 새 결정은 아래에 번호를 이어 붙인다.
형식: **결정** — 이유 / 대안 / 되돌리려면.

---

## D1. 공통 스키마는 JSON Schema 한 파일 + 자체 코드 생성기
- **결정**: `shared/schema.json`(JSON Schema `$defs`)을 원본으로 두고, `shared/codegen.py`(표준 라이브러리만 사용)가 `server/app/schemas/generated.py`(Pydantic v2)와 FE 저장소 `src/lib/api-types.gen.ts`(TS)를 만든다. `make lint`가 `--check`로 생성 파일이 최신인지 확인한다.
- **이유**: datamodel-code-generator·json-schema-to-typescript는 출력 이름 규칙·enum 표현이 서로 달라 두 쪽 타입을 같게 맞추기 번거롭다. 우리가 쓰는 범위(object, enum, nullable, 길이 제약)는 작아서 200줄 생성기로 충분하고, 결과가 결정적이다.
- **대안**: OpenAPI를 서버에서 뽑아 TS로 변환. 서버가 원본이 되어 "공통 스키마는 shared/" 요구와 맞지 않는다.

## D2. Next.js 15.5 + TypeScript 5.9 + Tailwind 4
- **결정**: Next 16이 나와 있지만 15.5 최신 패치(15.5.29)를 쓴다. TypeScript 7(네이티브 컴파일러)도 나왔지만 5.9를 쓴다.
- **이유**: 15.5는 아직 보안 패치가 나오고, App Router·rewrites·instrumentation 동작이 안정적이다. TS 7은 Next 15의 타입 검사 연동이 검증되지 않았다.
- **되돌리려면**: FE 저장소 `package.json`의 버전만 올리면 된다. Next 16에서는 `middleware`가 `proxy`로 바뀌지만 이 앱은 middleware를 쓰지 않는다.

## D3. 한국어 토크나이저: kiwi(정확) + lite(가벼움) 두 가지
- **결정**: `YEOUN_TOKENIZER=auto|kiwi|lite`. 로컬·유료 서버는 kiwipiepy, Render 무료(512MB)는 lite(규칙 기반 조사·어미 떼기 + 글자 2-gram).
- **이유**: kiwipiepy 기본 모델(cong)은 한 프로세스에서 약 350MB를 쓴다(직접 측정: 로드 241MB → 토큰화 후 351MB). 512MB 인스턴스에서 FastAPI·Pillow·ffmpeg와 함께 돌리면 메모리 초과 위험이 크다.
- **검증**: `make eval`이 두 토크나이저 모두의 top-3 정확도를 보고한다.

## D4. DB는 PostgreSQL만 지원 (테스트도 PostgreSQL)
- **결정**: SQLite 대체 경로를 두지 않는다. 테스트는 `yeoun_test` DB를 쓴다.
- **이유**: 작업 큐에 `FOR UPDATE SKIP LOCKED`, 메타데이터에 JSONB를 쓴다. 배포 환경과 같은 DB로 테스트해야 마이그레이션 문제를 미리 잡는다.

## D5. 쿠키 세션 + CSRF 헤더
- **결정**: 로그인은 HttpOnly·SameSite=Lax 쿠키(서버에는 토큰의 sha256만 저장). 쓰기 요청(POST/PATCH/PUT/DELETE)은 `x-yeoun-request: 1` 헤더가 없으면 거절한다.
- **이유**: 브라우저는 Next rewrites로 같은 출처의 `/api`만 부르므로 쿠키가 1st-party다. 다른 사이트의 form은 사용자 정의 헤더를 붙일 수 없어 CSRF를 막는다.

## D6. 파일 암호화: 공간별 데이터 키(봉투 암호화), 한 번에 암호화
- **결정**: 공간마다 32바이트 DEK를 만들고 `YEOUN_MASTER_KEY`에서 HKDF로 유도한 키로 감싸 저장한다. 파일은 AES-256-GCM 한 덩어리로 암호화하고 저장소 키를 AAD로 묶는다.
- **이유**: 파일 크기 상한(무료 25MB)이 있어 스트리밍 암호화가 꼭 필요하지 않다. 공간을 지우면 감싼 키도 사라져 저장소에 사본이 남아도 복호화할 수 없다(crypto-shredding).
- **주의**: 마스터 키를 바꾸거나 잃으면 기존 파일을 모두 읽을 수 없다. 키 교체 기능은 아직 없다(STATUS.md).
- **자막·태그는 DB에 평문**: 검색하려면 자막 텍스트가 필요하다. DB 접근 통제와 삭제로 보호한다.

## D7. API 오류는 한 가지 형식
- **결정**: 모든 오류는 `{"error": {"code", "message_ko"}}`. 검증 오류(422)도 `invalid_input`으로 바꾸고 입력값은 로그에 남기지 않는다.

## D8. 로그에 민감 정보 남기지 않기
- **결정**: uvicorn 접근 로그를 끄고, 실제 경로 대신 라우트 템플릿(`/api/spaces/{space_id}/clips`)만 남긴다. 토큰·키 모양 문자열은 로그 필터가 가린다. 파일명·자막은 로그 메시지에 넣지 않는다(ID만).

## D9. 작업 큐는 PostgreSQL 표 + 같은 프로세스 스레드
- **결정**: `jobs` 표를 `FOR UPDATE SKIP LOCKED`로 하나씩 가져간다. `YEOUN_WORKER_INLINE=true`면 API 프로세스 안 스레드가, 아니면 `python -m app.worker`가 처리한다. 잠금 20분이 지난 `running` 작업은 다시 가져간다(최대 3번).
- **이유**: Render 무료 등급엔 백그라운드 워커가 없고 Redis도 없다. 서버가 잠들어 처리 중 끊겨도 깨어나면 이어서 처리된다.

## D10. 정규화 오디오는 임시로만, 클립은 미리 잘라 저장
- **결정**: 원본(암호화)과 클립 mp3(암호화)만 저장하고, 16kHz WAV는 처리 중 임시 폴더에만 둔다. 클립은 처리 때 ffmpeg로 앞뒤 0.3초 여유를 두고 잘라 둔다.
- **이유**: 무료 DB 1GB에 WAV(분당 약 2MB)를 넣을 수 없다. 클립을 미리 잘라 두면 재생 때 ffmpeg를 다시 돌리지 않아도 된다(사파리 Range 요청도 단순해짐).

## D11. 키가 없을 때의 STT는 '자막을 지어내지 않는다'
- **결정**: mock STT는 테스트 fixture(파일 sha256로 찾음)가 있을 때만 자막을 주고, 그 밖에는 ffmpeg silencedetect로 말소리 구간만 나눠 자막을 비워 둔다. 사용자는 목소리 확인에서 자막을 적을 수 있다.
- **이유**: 원칙 1(말은 원본만)은 자막에도 적용된다. 그럴듯한 가짜 자막은 그 사람의 말을 지어내는 것과 같다.

## D12. 화자는 파일마다 따로, 사용자가 고른다
- **결정**: 화자 분리 결과는 파일 단위(`목소리 1`, `목소리 2`)이고, 파일마다 "이 목소리가 누구예요?"를 고른다. 파일을 건너 같은 사람을 자동으로 묶지 않는다. 화자 분리가 없으면 파일 전체를 한 목소리로 두고 클립별로 뺀다.
- **이유**: 파일 간 화자 매칭에는 목소리 임베딩 모델이 필요한데 이 환경에서는 가중치를 받을 수 없다. 잘못 묶으면 다른 사람의 말을 그 사람 말처럼 들려줄 위험이 있다.

## D13. 대화 내용은 서버에 저장하지 않는다
- **결정**: 대화 기록은 브라우저 탭(sessionStorage)에만 남는다. 서버는 하루 대화 횟수만 센다.
- **이유**: 대화에는 슬픔·위기 신호 같은 매우 민감한 내용이 담긴다. 기능상 서버 보관이 꼭 필요하지 않다.

## D14. Anthropic은 공식 SDK, OpenAI·Gemini는 REST(httpx)
- **결정**: Claude 호출은 공식 `anthropic` SDK(키는 `YEOUN_ANTHROPIC_API_KEY`에서만 받아 `api_key=`로 직접 넘김), 구조화 출력(`output_config.format` JSON 스키마), `effort: "low"`. OpenAI·Gemini는 SDK 없이 httpx로 부른다.
- **이유**: Anthropic SDK는 권장 경로이고, SDK 기본 동작(ANTHROPIC_API_KEY 읽기)은 키를 직접 넘겨 막는다. OpenAI·Gemini SDK까지 넣으면 이미지·메모리가 커진다. 모든 공급자는 쓸 때만 불러온다(lazy import).
- **검증 한계**: 이 개발 환경은 GitHub·패키지 저장소만 열려 있어 실제 공급자 호출은 시험하지 못했다(STATUS.md).

## D15. LLM 출력은 서버가 한 번 더 거른다 (guard)
- **결정**: 스키마 검증 뒤 ① 후보 밖 `clip_id` 버림 ② 자막에 없는 말을 따옴표로 인용하면 그 문장 버림 ③ `엄마: …` 같은 대사 형식 버림 ④ 길이 제한 ⑤ 정해진 태그 목록 밖 태그 버림. 버린 이유(개수)만 로그에 남긴다. 실패·이상 출력이면 규칙 기반으로 계속 답한다.
- **위기 분류**: LLM의 위험도는 규칙보다 높일 때만 따른다(낮출 수 없음). 기억 대화(D27)도 11/15부터 같은 원칙으로 답장 LLM의 위험도를 쓴다.

## D16. '맞는 녹음 없음' 기준은 낱말·태그 일치도
- **결정**: 각 후보의 confidence = 질문의 대표 낱말(idf 가중, 한 글자는 절반)과 태그 중 맞은 비율(+확장어 일부). 기본 기준 0.34(`YEOUN_MATCH_THRESHOLD`). 0.12 아래면 LLM을 부르지 않는다.
- **이유**: BM25 점수는 질문마다 크기가 달라 기준선으로 쓰기 어렵다. 비율은 질문 길이와 상관없이 비교할 수 있다. 골든 세트의 '맞는 녹음 없음' 4문항으로 확인한다.

## D17. 규칙 기반 검색: 사투리 정규화 + 개념 묶음
- **결정**: 검색용 사본에만 사투리를 표준어로 바꾸고(`묵어라→먹어라`, `할매→할머니` …), 가족 녹음에 흔한 주제(식사·건강·시험·날씨·그리움 …) 개념 묶음으로 질문을 확장하고 태그를 붙인다. 원문 자막은 바꾸지 않는다.
- **이유**: 어르신 녹음의 STT 결과는 사투리 표기가 많고, 사용자는 다른 말로 묻는다("회사 그만두고 싶어" ↔ "회사 일이 힘들면 쉬어도 된다").
- **과적합 주의**: 개념 묶음은 특정 샘플 문장이 아니라 일반 주제로 만들었다. eval이 틀린 질문을 맞추려고 문장별 규칙을 넣지 않았다(lite 1문항은 남겨 둠).

## D18. 미리 남기기 링크·가족 초대는 1회용 토큰, 서버엔 해시만
- **결정**: 토큰(24바이트)은 만들 때 한 번만 보여 주고 DB엔 sha256만 저장한다. 녹음 링크는 기간(기본 7일)이 지나거나 '다 했어요'를 누르면 끝난다(같은 질문 다시 녹음은 끝내기 전까지 교체). 초대는 7일, 한 사람.
- **로그**: 토큰이 든 경로는 라우트 템플릿(`/record/{token}`)으로만 남긴다.

## D19. 링크 주소는 설정 → 브라우저 Origin 순서
- **결정**: `YEOUN_PUBLIC_WEB_URL`이 없으면 요청의 `Origin`(https 또는 localhost만 신뢰)을 쓴다.
- **이유**: Render에서 웹 주소를 미리 알기 어렵다. 브라우저가 붙이는 Origin은 다른 사이트가 위조할 수 없다.

## D20. 재생은 서버가 복호화해서 내려준다 (서명 URL 15분)
- **결정**: `/api/media/{c|p}/{id}?exp=&sig=` (HMAC). 쿠키 없이 `<audio>`가 열 수 있고, Range 요청을 지원한다.
- **이유**: 파일이 앱 키로 암호화되어 있어 S3 presigned URL로는 재생할 수 없다. 클립이 작아(30초 이하) 매번 복호화해도 부담이 작다.

## D21. 샘플 공간은 서버 시작마다 확인, 바뀐 게 없으면 그대로
- **결정**: fixture 내용·녹음 파일 목록·토크나이저·이번 달로 지문을 만들어 시스템 사용자 설정에 저장하고, 같으면 건너뛴다. 샘플은 시스템 사용자 소유, 누구나 읽기 전용.
- **'1년 전 오늘' 샘플**: fixture의 `@one_year_ago` 클립은 오늘과 같은 월·일 중 기일 이전의 가장 최근 해로 둔다(가상 인물의 기일 뒤 날짜가 되지 않게).
- **녹음 파일**: 팀원 녹음(`fixtures/demo/demo-XX.*`)은 실제 사람 목소리라 기본으로 커밋하지 않는다(.gitignore). 배포에 쓰려면 녹음한 사람의 동의 뒤 직접 커밋한다.

## D22. 시간대는 한국 시간(KST) 기준
- **결정**: 저장은 UTC, '하루'(대화 한도), '오늘'(지난해 오늘), 알림 금지 시간(22시~8시)은 KST로 계산한다.

## D23. 무료 등급 한도 기본값
- **결정**: 파일 25MB, 공간 150MB, 사용자 300MB, 하루 대화 150회, 샘플 체험 분당 60회(접속 주소별, 배포 값. 코드 기본값은 20).
- **이유**: 무료 DB 1GB를 친구 5~6명이 나눠 쓰는 정도. 레이트 리밋은 메모리 기반이라 API 인스턴스가 하나일 때만 정확하다(무료 등급은 하나).

## D24. e2e는 실제 서버처럼, 시스템 로케일은 UTF-8
- **결정**: `scripts/e2e.sh`가 전용 DB(`yeoun_e2e`)·임시 저장소·mock 공급자로 API와 production 빌드 웹을 띄우고 Playwright(가짜 마이크)를 돌린다. `LANG=C.UTF-8`을 강제한다.
- **이유**: 로케일이 없으면 Playwright가 한글 파일 경로(`통화 녹음 엄마_….m4a`)를 조용히 못 읽는다(직접 확인).

## D25. Docker 이미지는 이 환경에서 끝까지 빌드하지 못함
- **결정**: Dockerfile은 표준 `python:3.12-slim` + `apt-get install ffmpeg`로 둔다. 이 개발 환경은 Docker Hub(429)와 Debian 미러(프록시 405) 접근이 막혀 이미지 빌드를 끝까지 확인하지 못했다. 대신 `requirements.lock`만으로 새 가상환경을 만들고 `start.sh`를 staging 설정으로 실행해 전체 흐름(가입·업로드·처리·대화·샘플)을 확인했다(API 최대 메모리 약 166MB).
- **사람이 할 일**: 첫 Render 배포 때 빌드 로그 확인(TODO-team.md).

## D26. 접근성·화면
- **결정**: 모바일 우선, 버튼 최소 높이 44~48px, 큰 글씨 옵션(루트 글자 17→20px, 계정에 저장), 녹음하는 쪽 화면은 항상 큰 글씨(20px 기준)와 160px 녹음 버튼. 그 사람의 말은 따옴표·세리프, 여운 안내는 남색 말풍선과 라벨로 구분.
- **글꼴**: Pretendard(npm 패키지). 세리프는 시스템 글꼴에 맡긴다(웹 폰트 크기 때문).

## D27. 대화는 메신저처럼 답장 하나, 네 종류 (11/14)
- **결정**: `POST /spaces/{id}/talk` 는 답장 하나를 돌려준다. 원본 녹음이 그대로 답이 되면 original(DB 자막 원문 + 실제 녹음), 아니면 근거 녹음 1~3개를 붙인 'AI가 만든 말'(generated), 근거가 없거나 금지 주제면 여운 안내(guide), 위기 신호면 crisis 로 멈춘다. 위기는 규칙이 먼저 보고, 답장 LLM이 함께 낸 위험도가 더 높으면 그쪽을 따른다(11/15).
- **이유**: 녹음을 여러 개 나열하는 건 검색이지 대화가 아니라는 피드백. 녹음에 없는 말에 답이 막히지 않게 하되, 그분 말처럼 지어내지 않도록 만든 말은 눈에 띄게 표시하고 근거를 붙인다. 유언·돈·용서·의료·법률은 요청과 만든 답 양쪽에 규칙을 건다.
- **되돌리려면**: 화면이 옛 `/chat` 을 부르게 하면 된다(서버에 남아 있음).

## D28. 말투 카드는 말하기 특징만, 서버 메모리에 잠시 (11/14)
- **결정**: 그분 녹음 자막 최대 80개에서 부르는 말·자기 호칭·어미·자주 쓰는 표현·주제만 뽑는다. 성격을 짐작해 평가하지 않는다. 공간의 index_version 이 같으면 다시 쓴다. DB 에 저장하지 않는다.
- **주의**: 공간을 지울 때 이 캐시를 비우는 코드가 아직 없어, 서버가 다시 시작될 때까지 메모리에 남는다(privacy.md에 적음).

## D29. 목소리가 하나로 나온 녹음은 내용으로 나눠 제안, 확정은 사람 (11/14)
- **결정**: 통화·영상이 한 목소리로만 나오면 LLM이 문장별로 A/B 를 붙인다(`ai/content_split.py`). 누가 그분인지는 목소리 확인에서 사람이 고른다. 그분을 부르며 시작하는 말('엄마, …')은 확인이 틀려도 그분 말로 쓰지 않는다.
- **이유**: 가족의 말이 그분 말로 쓰이는 것이 가장 큰 위험이다(D12의 위험을 줄이는 방법). 합성 음성 테스트 통화에서 딸의 말이 할머니 말로 쓰인 일이 있었다.

## D30. 기억책은 우왕톤에서 빼고, 목소리 합성은 하지 않는다 (11/14)
- **결정**: 기억책·기억 통화(`0002_books`)를 `0003_drop_books` 로 지우고 기억 대화만 남긴다. 0002 파일은 배포 DB 에 이미 적용된 기록이라 지우지 않았다. 그분 목소리 합성은 음성 복제가 되는 서비스(fal)가 유료라 이번 제출에 넣지 않는다(부품은 별도 PR 초안으로 남김).

## D31. 기억 대화 보강: LLM 위험도, 관련 녹음 없는 사실 답 거르기 (11/15)
- **결정**: 답장 LLM이 `risk`(none/watch/high)와 `kind`(feeling/fact)를 함께 낸다. 위험도는 규칙보다 높일 때만 따른다. 검색 일치도 0.25 이상 녹음을 '관련 녹음'으로 표시하고, `kind`가 feeling이 아니면 근거에 관련 녹음이 있어야 내보낸다.
- **이유**: 검증에서 규칙이 처음 보는 위기 표현 10개를 하나도 못 잡았고(0/10), 녹음에 없는 질문 2/4에 사실·조언을 지어냈다. 보강 뒤 같은 메시지로 10/10, 4/4.
- **대가**: 엄격해져서 녹음에 있는 내용도 안내로 끝나는 경우가 생길 수 있다(검증에서 1개). 0.25는 샘플 공간 기준 값이라 실제 공간에서 다시 봐야 한다.
