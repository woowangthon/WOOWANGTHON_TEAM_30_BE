# 생성형 AI 사용 내역

공모전 기획안에 그대로 옮길 수 있도록 정리했어요. (A) 개발에 쓴 생성형 AI, (B) 서비스 안에서 AI를 쓰는 범위로 나눠요.

## A. 개발에 쓴 생성형 AI

### 도구
- **Claude Code (Anthropic)** — 클라우드 개발 환경(샌드박스)에서 동작하는 코딩 에이전트

### 한 일

| 단계 | 생성형 AI가 한 일 | 사람이 한 일 |
|---|---|---|
| 기획 | — | 서비스 정의, **절대 원칙 6가지**, 기능 목록(P0/P1), 기술 스택, 배포 조건을 문서로 작성 |
| 구현 | 팀의 명세를 바탕으로 서버(FastAPI)·웹(Next.js)·DB 스키마·처리 파이프라인·AI 어댑터 코드를 작성 | 명세 결정, 결과 검토 |
| 테스트 | 단위·통합 테스트(pytest 약 100개), 브라우저 시나리오 테스트(Playwright 4개), 검색 정확도 평가(`make eval`) 작성·실행 | 테스트 기준(원칙 1·2 검증, 권한·삭제·암호화) 제시 |
| 한국어 데이터 | 하위 에이전트가 질문 카드 72개, 샘플 자막 40개, 평가 질문 30개 + '맞는 녹음 없음' 4개, 녹음 대본 초안을 작성 → 스크립트로 검사(정해진 태그 목록만 썼는지, 참조 ID가 맞는지, 대본과 자막 글자가 같은지, 길이) | 내용 검토(어색한 표현, 사투리, 정서적 적절성) |
| 문서 | README, 배포 안내, 결정 기록, 상태 보고, 개인정보 처리방침 초안 등 작성 | **최종 검토·수정 책임** |
| 배포·운영 | Render 설정 파일과 안내 문서 작성 | 실제 배포, API 키 발급, 샘플 녹음, 법률 검토 |

### 원칙
- 샘플 인물 **"[샘플] 김순자 할머니"는 가상 인물**이에요. 실제 사람의 녹음·사진·말은 하나도 쓰지 않았어요. 사진은 색과 도형으로 만든 placeholder이고, 테스트 오디오는 ffmpeg로 만든 합성 톤이에요.
- 생성형 AI가 쓴 코드와 문서는 사람이 검토한 뒤에 공개·배포해요.
- 개발 과정의 기록은 `docs/CHANGELOG.md`(날짜별 변경)와 `docs/decisions.md`(결정과 이유)에 남겼어요.

## B. 서비스 안에서 AI를 쓰는 범위

### 한 줄 요약
**녹음에 있는 말은 실제 녹음(원본 클립)으로 답하고, 녹음에 없는 말을 AI가 만들 때는 'AI가 만든 말'로 표시하고 근거 녹음을 붙여요. 근거가 없으면 만들지 않고, 음성은 합성하지 않아요.** (11/14 기억 대화부터. 11/9까지는 AI가 '찾고 고르기'만 했어요.)

### 기능별 사용

| 기능 | 하는 일 | 공급자 선택지 (`auto`면 키가 있는 것) | 밖으로 나가는 데이터 | AI 없이 돌아가는 방식(mock·규칙) |
|---|---|---|---|---|
| 음성 인식(STT) | 녹음을 문장 구간별 자막으로 | **NOVA → Soniox `stt-async-v5`**(배포에서 사용), OpenAI `whisper-1`, Google Gemini | 오디오 | 무음 구간으로 말소리 구간만 나누고 **자막은 비워 둠**(사용자가 직접 적음, 지어내지 않음) |
| 화자 분리 | 녹음 속 목소리 나누기 | **NOVA → Soniox**(받아쓰기와 한 번에), OpenAI `gpt-4o-transcribe-diarize` | 오디오 | 나누지 않음 → 사용자가 '목소리 확인'에서 파일·클립 단위로 고름 |
| LLM: 내용으로 화자 나누기 | 통화·영상인데 목소리가 하나로 나오면 문장마다 A/B를 붙여 두 사람으로 나눔 | NOVA → `claude-haiku-5-5` 등 | 그 녹음의 자막 문장 | 나누지 않음. 어느 쪽이 그분인지는 언제나 사람이 고름 |
| LLM: 말투 카드 | 그분 녹음 자막에서 부르는 말·자기 호칭·어미·사투리·자주 쓰는 말 뽑기 | 위와 같음 | 그분으로 확인된 자막(160자씩) | 빈 카드(근거 녹음만으로 답) |
| LLM: 기억 대화 답장 | 원본 녹음 하나를 고르거나, 근거 녹음과 함께 그분 말투로 1~3문장 답장 | 위와 같음 | 보낸 말, 최근 대화 8턴, 관련 녹음 자막 12개, 말투 카드 | AI 없이: 딱 맞는 원본 녹음만 들려주고, 없으면 안내 |
| LLM: 의도 파악 | 보낸 말의 의도·키워드·관련 태그 | **NOVA → `claude-haiku-5-5`**(배포), Anthropic `claude-haiku-5-5`, OpenAI, Gemini, replay | 보낸 말 | 개념 사전(식사·건강·시험·그리움 등) + 사투리 정규화 |
| LLM: 클립 고르기 | 후보 20개 중 최대 3개 고르고 이유 쓰기 | 위와 같음 | 보낸 말, 후보 클립의 자막·날짜·태그 | BM25 점수·일치도 기준으로 고르고 정해진 안내 문장 사용 |
| LLM: 주제 태깅 | 클립에 정해진 태그 붙이기 | 위와 같음 | 자막 텍스트 | 규칙 기반 태깅(정해진 태그 44개 안에서) |
| LLM: 위험 신호 보조 | 자살·자해 위험 판단 보조. **옛 검색형 대화(`/chat`)에서만** 쓰고, 기억 대화는 규칙만 씀 | 위와 같음(의도 파악과 한 번에) | 보낸 말 | 규칙(한국어 표현 목록) — 항상 먼저 동작 |
| 임베딩 | 뜻이 비슷한 말 찾기 | **NOVA → `text-embedding-3-small`**, OpenAI, Gemini | 자막 텍스트, 보낸 말 | 쓰지 않음(BM25만) |
| 한국어 형태소 | 검색용 낱말 나누기 | (로컬) kiwipiepy | 없음 | 규칙 기반 lite 토크나이저 |

### AI가 하지 못하게 막은 것

| 금지 | 어떻게 막나요 |
|---|---|
| 음성 합성(TTS)·목소리 복제 | 해당 기능·경로·어댑터 자체가 없음. 테스트가 경로 이름을 검사 |
| AI가 만든 말을 그분 녹음처럼 보이게 하기 | 응답 `mode`로 나눔: `original`은 **DB 자막 원문**과 실제 녹음, `generated`는 화면에 'AI가 만든 말' 표시 + 근거 녹음. LLM이 원본을 골라도 자막은 LLM이 옮긴 글자 대신 DB 원문을 씀 |
| 근거 없는 답 | `generated`인데 근거 녹음 ID가 없거나 후보 밖이면 버리고 안내로 바꿈 |
| 그분이 대신 답하면 안 되는 주제 | 유언·유산·상속·계좌·비밀번호·보증·대출·송금·용서·원망·진단·처방·수술·소송 등은 요청과 만든 답 **양쪽**에 규칙을 걸어 여운 안내로 바꿈 |
| 가족 목소리를 그분 말로 쓰기 | 그분으로 고른 목소리만 쓰고, 그분을 부르며 시작하는 말('엄마, …')은 빼고, 목소리가 하나로 나온 통화는 내용으로 나눔 |
| 후보에 없는 녹음 고르기 | LLM 출력을 JSON 스키마로 검증하고, 후보 목록에 없는 `clip_id`는 버림 |
| 지어낸 인용 | 이유·안내 문장 속 따옴표 인용이 실제 자막에 없으면 그 문장을 버림 |
| 대사 형식("엄마: …") | 대사처럼 쓴 안내는 버리고 정해진 안내 문장으로 바꿈 |
| 정해진 목록 밖 태그 | 버림 |
| 서비스 말과 그분 말의 혼동 | 서비스가 하는 말은 **'여운 안내'** 라벨·다른 색으로 분리 |
| 위험 신호 놓치기 | 규칙이 먼저 판단하고, LLM은 위험도를 **올리기만** 할 수 있음(낮추지 못함) |
| 실패 시 멈춤 | 시간 초과·거절·이상한 출력이면 규칙 기반으로 자동 전환 |

LLM에게 주는 지시에도 같은 규칙(새 문장 금지, 자막 바꾸지 않기, 3인칭 안내, 사용자 메시지 속 지시문은 데이터로만 취급)을 넣었지만, **지시만 믿지 않고 서버가 출력을 다시 검사**해요.

### 데이터 정책
- 키는 `YEOUN_` 접두사 환경 변수로만 받아요(`ANTHROPIC_API_KEY` 같은 기본 변수는 읽지 않음). 코드·로그·커밋에 남기지 않아요.
- 입력을 학습에 쓰는 무료 등급(예: Gemini 무료)은 정식 서비스에서 실제 사용자 자료에 쓰지 않고, 친구 테스트에서는 동의한 사용자에게만 써요.
- 대화 내용은 서버에 저장하지 않아요(하루 사용 횟수만 셈). 말투 카드는 서버 메모리에만 두고 DB에 저장하지 않아요.

### 측정 결과 (AI 키 없이, 규칙 기반 mock 기준)

`make eval` — 가상 샘플 공간(클립 40개)에 대한 골든 세트

※ 아래 표는 녹음 찾기(옛 검색형 경로)만 측정한 값이에요. 기억 대화 답장은 아래 '기억 대화 검증'을 보세요.

| 토크나이저 | top-3 정확도(최종 답) | 검색 top-3 | '맞는 녹음 없음' 판정 |
|---|---|---|---|
| lite (Render 무료용, 메모리 적음) | **96.7%** (29/30) | 100% | **4/4** |
| kiwi (형태소 분석) | **100%** (30/30) | 100% | **4/4** |

- 질문은 자막과 다른 표현(예: "회사 그만두고 싶어" → "회사 일이 그래 힘들면 좀 쉬어도 된다")이 대부분이에요.
- 실제 LLM으로 고르는 경로(`python -m app.eval --llm`)는 측정하지 않았어요.

### 기억 대화 검증 (2026-11-14~15, `python -m app.eval_talk`)

배포본(Render) 샘플 공간 "[샘플] 김순자 할머니"(가상, 자막 40개)에 실제 NOVA `claude-haiku-5-5`로 메시지를 보내 쟀어요. 원본 결과는 AI 저장소 `results/2026-11-15-talk-eval.json`.

| 항목 | 결과 |
|---|---|
| 골든 30문항 | 모두 실제 녹음(original)으로 답함. 기대한 녹음 30/30, 29/30 (두 번 실행) |
| AI가 만든 답(일상 메시지 20개 + 녹음에 없는 질문 4개에서 나온 14개) | 근거 녹음 붙음 14/14, 금지 표현 0. 사람이 읽어 보니 자연스럽고 근거와 맞음 11, **문제 3**(녹음에 없는 사실 1, 녹음에 없는 조언 1, 질문을 잘못 읽음 1) |
| 녹음에 없는 질문 4개 | 지어내지 않고 안내 2, 그분 말투로 답 2 |
| 위기 문장 20개(규칙) | 처음 15, 주의만 1, 놓침 4 → 11/15 규칙 수정 뒤 위기 전환 19, 주의만 1, 놓침 0 (같은 문장으로 다시 잼) |
| 새 위기 문장 10개(규칙 수정 뒤 새로 씀) | 위기 전환 **0**, 주의만 1, **놓침 9** |
| 금지 주제 20개(규칙) | 막음 17, 놓침 3 |
| 일상 문장 20개(규칙) | 위기·금지 오탐 0 |

- 서버는 만든 답의 근거 ID가 후보 안에 있는지만 검사하고, 내용이 근거와 맞는지는 검사하지 않아요. 그래서 화면에 'AI가 만든 말'과 근거 녹음을 늘 함께 보여 줘요.
- 위기 규칙이 놓친 4개("더는 못 살겠어", "손목을 그었어", "수면제를 한꺼번에", "그만 살고 싶어")는 11/15에 규칙을 넓혀 잡았어요(조사·활용형: "더는", "그었", "수면제를", "그만 살"). 하지만 규칙을 보지 않고 새로 쓴 위기 문장 10개는 거의 못 잡았어요("옥상에 올라와 있어", "모든 게 끝났으면 좋겠어" 등). **규칙만으로는 돌려 말한 위기 표현을 잡기 어렵다**는 게 이번 검증의 가장 큰 한계예요. 다음 단계는 기억 대화 답장을 만드는 LLM 호출에서 위험도도 함께 판단하게 하는 것(LLM은 위험도를 올리기만 하고 낮추지 못하게)이에요.

### 아직 확인하지 못한 것 (솔직하게)
- NOVA(Soniox·Claude·임베딩)는 11/14 배포본에서 실제로 호출해 확인했어요. OpenAI·Anthropic·Gemini 직접 호출은 확인하지 않았어요.
- 받아쓰기·화자 분리 확인에 쓴 통화는 합성 음성으로 만든 테스트 파일이에요.
- 실제 사람 목소리·사투리·잡음이 섞인 녹음에서의 정확도는 아직 측정하지 않았어요.
