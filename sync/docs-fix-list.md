## 먼저 읽을 것

가장 큰 차이는 하나다. 문서 대부분이 11월 9일에 정한 "말은 원본만, AI는 찾고 고르기만" 구조를 설명하는데, 지금 main 의 대화 화면은 11월 14일에 들어간 기억 대화(메신저형, `POST /api/spaces/{id}/talk`)다. 이 대화는 녹음에 없는 말을 그분 말투로 새로 만들어 'AI가 만든 말'로 표시한다(`server/app/services/talk.py` 199~205줄, `server/app/ai/llm.py` 139~155줄). FE 첫 화면과 대화 화면은 이미 그렇게 안내하는데, FE 개인정보·도움 안내 화면과 BE·AI 문서는 아직 옛 설명이다. 심사위원이 같은 서비스에서 서로 다른 말을 읽게 된다.

합성(그분 목소리를 만드는 것)은 지금 main 에 없다. 그래서 "목소리를 합성하지 않는다"는 문장 자체는 지금 사실이다. 다만 같은 문장 안에 "새 문장도 안 만든다"가 붙어 있는 곳이 많고, 그 부분은 합성을 넣든 빼든 틀렸다. 이 문서는 문장마다 이 점을 갈라서 적었다.

- 두 경우 같음: 합성을 넣든 빼든 같은 문장으로 고친다.
- 빼는 경우: 합성을 넣지 않는다. 합성 문장은 그대로 두고, 틀린 부분만 고친다.
- 넣는 경우: 합성을 연결한다. 초안은 BE 브랜치 `docs/VOICE_SYNTHESIS.md` 5장을 따랐고, 줄 번호와 지금 문장은 main 에서 다시 확인했다. 연결해서 실제로 동작을 확인하기 전에는 쓰지 않는다.

점검 방법: `git show origin/main:<경로>` 로 문서와 코드를 읽었고, main 을 임시 폴더(저장소 밖)에 풀어 `python -m app.eval` 과 `pytest --collect-only` 를 돌렸다. 배포본은 `/api/health`, `/api/config`, 샘플 공간 대화 3건만 호출했다. 저장소는 어느 것도 고치지 않았다.
